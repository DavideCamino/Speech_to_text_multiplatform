## 1. Unused code

### U1. Implicit first-model worker — unused by the application, still exercised by tests (Medium)

**Evidence:** `src/llm/worker.rs:41–64,81–122`; `src/llm/client.rs:203–230`; `src/ui/rewrite.rs:362–415,450–500`; `tests/llm.rs:62–201,400–408`. Only the public `llm::start` supplies `options = None`. That branch calls `Client::model()`, fetches `/v1/models` and selects `/data/0/id`. The UI instead discovers models, explicitly loads a selection, or generates with that selection. Six integration-test call sites still use `start`, including the stalled-cancellation, partial-stream and malformed-stream cases. These are useful tests, not obsolete behavior to discard.

**Recommendation:** Drive those scenarios through configured discovery/generation with a selected model. Keep the `/v1/models` fallback in `Client::models`: it is live even without `Client::model`. Replace the private combination of `Option<rewrite>`, `Option<Options>` and `load_only` with named operations (discover/load/generate). Deprecate the public implicit entry point or retain a documented compatibility wrapper depending on the library contract; removing it outright is an API break.

### U2. Direct settings load/save — no in-tree callers (Medium)

**Evidence:** `src/settings.rs:80–98,143–218`; `src/ui/mod.rs:61`. Neither public `Settings::load()` nor `Settings::save()` has a caller in the application, examples or tests. `save_in` *does* have test callers. Startup now returns the settings and a writer whose replace permission comes from inspecting the original file. Direct `save()` instead calls `write_in(directory, true)`. It is not an equivalent shortcut if an unreadable file must be preserved.

**Recommendation:** Keep the startup/writer route canonical. If these public methods support external consumers, document the unconditional-replacement behavior and offer a policy-aware migration; otherwise deprecate them. Keep tests of replacement and no-clobber writes rather than retaining a production wrapper solely for fixture setup. This is an API hazard, not evidence that the current UI overwrites settings.

### U3. `reqwest`'s `stream` feature is not needed for `Response::chunk()` (Low)

**Evidence:** `Cargo.toml` enables `rustls-tls`, `json` and `stream`. The model downloader and LLM client (`src/model.rs:224`, `src/llm/client.rs:97,182,210,255`) read incrementally with `chunk()`. In locked reqwest 0.12.28 that method is unconditional; `bytes_stream()` is feature-gated. No first-party caller uses the latter or a streaming request body. `cargo tree -e features -i reqwest` shows this package enabling `stream`.

**Recommendation:** Remove only the feature, not the incremental reading, size limits or cancellation checks. Reconcile `Cargo.lock` and the Flatpak Cargo source inventory if dependency resolution changes; run the streaming and download tests after the change.

## 2. Redundant code

### R1. Multiple queue-wide ETA calculations per GTK tick (High for large batches)

**Evidence:** `src/ui/mod.rs:36,118`; `src/ui/app.rs:147–162`; `src/ui/transcription_controller.rs:250–281,427–464`; `src/ui/audio_queue.rs:203–224,359–382`. Each `Progress` event immediately calls `refresh_file_progress`. `App::poll` calls it again after draining transcription; a full controls refresh calls it too. During a batch with known durations, each call sums completed fractions, walks pending files, formats the estimate and sets the label. A poll with P progress events and N files can therefore do O(P × N) work on the GTK thread although only the last label is visible. `try_iter().collect()` also has no per-tick limit: the channel has bounded capacity, but the worker can refill it while it drains. This is a cost visible in the code, not a measured latency claim.

**Recommendation:** Apply state events in order but coalesce progress *presentation* at the end of a bounded poll. Preserve each file's latest fraction before `FileFinished` advances the batch, including for failed/incomplete files; never collapse final segments or file boundaries. Keep a periodic update for elapsed time and late duration metadata, and keep immediate hide/reset on cancel and clear. Only cache duration sums if profiling after coalescing still warrants it.

### R2. Preferences and recovery implement the same file publication sequence (Medium)

**Evidence:** `src/settings.rs:98–137` and `src/recovery.rs:73–112` independently create the parent, stage a tempfile in it, write bytes, `sync_all`, and choose `persist` or `persist_noclobber`. A fix to this sequence currently has to land twice. The *reason* replacement is permitted is different: inspecting settings at startup is not the same as owning a recovery snapshot.

**Recommendation:** Put only the byte-publication primitive in `src/storage.rs`, with an explicit replace/create-only choice. Preserve caller-specific validation, recovery size limits, temp naming, quarantine decisions and user-facing errors (especially `AlreadyExists`). Do not merge the two persistence controllers or generalize model import/download into this helper.

### R3. Single-file and batch terminal results share a type but not a meaning (Low)

**Evidence:** `src/transcription/worker.rs:63–101,143–177`; `src/ui/transcription_controller.rs:221–244,306–400`; `examples/transcribe.rs:42–56`. The GUI routes even one selected file through `start_files`. `run_files` sends incomplete-input results via `FileFinished`; its successful terminal result is `Complete`. The microphone also maps success to `Complete`. Thus the GUI's terminal `Ok(IncompleteFile)` status is not produced by either current GUI path. **Do not delete `IncompleteFile`:** the single-file public worker returns it directly to the example, and the GUI needs it at batch boundaries.

**Recommendation:** Extract batch-finish presentation from `poll_transcription` first. Document or type the distinction between per-file outcome and job termination before pruning the fallback; keep single-file callers' timestamp and completion semantics intact.

## 3. Refactoring

1. **Coalesce UI work first (R1).** Exercise a backlog spanning progress, a failed file, the next file's final segments and terminal completion. Check intermediate batch accounting, ordered timestamps, responsive polling, and a cleared final label. Compare ETA render counts per tick on a large synthetic queue rather than relying on wall-clock assertions.
2. **Migrate coverage before shrinking APIs (U1, U2).** Keep discovery fallback, explicit Apply, cancellation during a stalled body, early chunk delivery and malformed/truncated streams covered on the path used by the UI. Decide external compatibility separately from internal branch removal.
3. **Consolidate storage and clarify outcomes independently (R2, R3).** Run settings and recovery collision/quarantine tests against both publication modes. For transcription, retain tests for truncated single files, mixed batches and model setup failure before the first boundary. U3 is a separate manifest-only cleanup with its own dependency/packaging check.
