# Speech2Text — Code Review Report

**Date:** 2026-11-05  
**Version reviewed:** 0.1.0

## Brief description

Speech2Text is a Rust/GTK4/libadwaita desktop application that transcribes audio files and microphones locally using Whisper. It exports text/subtitles and optionally sends transcripts to a configured OpenAI-compatible llama.cpp server for rewriting.

## Most important features

- **Local multilingual recognition:** automatic or explicit language selection; audio is processed in memory rather than uploaded.
- **File transcription:** incremental decoding and conversion to 16 kHz mono, with bounded recognition windows rather than loading an entire recording.
- **Live microphone transcription:** input selection, level/time display, provisional text, overlapping-window reconciliation, and separate Stop and Cancel operations.
- **Hardware acceleration:** optional Vulkan, CUDA, Metal, and ROCm builds, with explicit backend selection and CPU mode.
- **Model library:** local model selection/import and explicit Tiny–Large V3 downloads with size and SHA-256 verification.
- **Transcript handling:** replace/append workflows, clipboard copying, TXT/SRT export, and warnings before discarding unexported results.
- **LLM rewriting:** configurable host/port/HTTPS, session-only authentication token, connection testing, streamed Markdown rendering, cancellation, and TXT/Markdown export.
- **Desktop integration and distribution:** saved preferences, keyboard shortcuts, background workers, asynchronous exports, Linux Flatpak and Windows installer/portable packaging workflows.

## Bugs found — ordered by importance

These are implementation findings, not claims that every failure was observed on real hardware. Conditional failures and reproduced cases are identified below.

### 1. High — Re-downloading a model can destroy the installed copy before replacement succeeds

**Location:** `src/model.rs:download` (approximately lines 195–199).

The downloader deletes an existing target and only then renames the verified staging file. A crash or rename failure between these operations leaves the installed model missing; error cleanup also deletes the staging file. Downloading a catalog entry can additionally overwrite a different imported model with the same filename without an overwrite-specific confirmation.

**Recommendation:** use a platform-safe atomic replacement or rollback strategy, and explicitly confirm replacement. Never delete the only installed copy before the replacement is safely committed.

### 2. Medium — Download staging files are shared and cleanup can delete another operation's data

**Location:** `src/model.rs:download` (lines 157, 174, 203).

Every download of a given model uses the same `<model>.part` path. Concurrent callers—for example, the GUI and `examples/download_model.rs`—can truncate or remove each other's staging files. Even an already-cancelled call reaches the unconditional error cleanup and removes an existing `.part` file that it never created. The GUI serializes its own jobs, but the public downloader has no cross-process protection.

**Recommendation:** use uniquely owned temporary files, as model import already does, and serialize publication to the final target.

### 3. Medium — Preference saves can corrupt the previous configuration

**Location:** `src/settings.rs:Settings::save`; startup fallback in `src/ui/mod.rs:build`.

`std::fs::write` truncates `settings.json` in place. A partial write, disk-full error, or interrupted process can leave invalid JSON and lose the previous settings. On the next launch, parsing fails and the application falls back to defaults; subsequent saves can overwrite the damaged configuration rather than preserving it for recovery.

**Recommendation:** write and flush a temporary file in the same directory, then replace atomically; preserve a backup or quarantine malformed settings.

### 4. Medium — Recognition output loses original spacing and gains unwanted spaces

**Location:** `src/transcription/engine.rs:Engine::transcribe`, `src/transcription/overlap.rs:captions`, `src/transcript.rs:Transcript::text`, and `src/ui/transcript_buffer.rs`.

Recognition fragments are trimmed and subsequently joined with unconditional ASCII spaces. This cannot preserve punctuation/subword boundaries or languages that do not normally separate words with spaces. A standalone probe using the actual reconciler and transcript code turns adjacent fragments `你`, `好`, `。` into `你 好 。` instead of `你好。`. This is a formatting defect independent of Whisper's recognition accuracy; actual occurrence depends on its segmentation.

**Recommendation:** retain original token-boundary/whitespace information and apply language-aware joining consistently to the UI, TXT, provisional text, and SRT.

### 5. Medium — The UI performs filesystem I/O on every polling tick

**Location:** `src/ui/mod.rs:refresh`, `src/ui/rewrite.rs:poll_rewrite`, and `src/settings.rs:Settings::save`.

The 80 ms poll calls `poll_rewrite()`, which unconditionally calls `refresh()`. `refresh()` checks the selected model with `Path::is_file()` on GTK's main thread, even while idle. Since users can select a model at its original location, a slow or disconnected network mount can repeatedly block the interface. Preference writes also happen synchronously on the UI thread.

**Recommendation:** cache model availability and validate it asynchronously when needed; move preference writes off the main loop. The call path is confirmed by inspection; a slow-mount freeze was not reproduced during this review.

### 6. Low — User-facing license information is inconsistent

**Location:** `src/ui/menu.rs:about`, `build-aux/windows/installer.iss`, and `data/io.github.davidecamino.Speech2Text.metainfo.xml`.

The About window declares MIT only, and the installer displays only the project's MIT license. However, AppStream declares `MIT AND GPL-3.0-or-later`, and the README explicitly notes the GPL-licensed `gtk-markdown` dependency and combined-binary distribution obligations. Dependency notices are collected by packaging, but the main license presentation remains misleading.

**Recommendation:** distinguish the project's source license from the combined application's licensing in About and the installer, and verify corresponding-source delivery before release. This finding concerns inconsistent presentation, not a legal determination of compliance.

## Missing features / remaining product gaps

These are absent capabilities or documented limitations, not necessarily bugs or agreed requirements.

- **Transcript correction and subtitle editing:** no editable transcript, timestamp editor, synchronized audio playback, or subtitle preview.
- **Session recovery:** no opt-in autosave, transcript/project history, crash recovery, or reopening a previous working session. Audio is not retained for retrying failed recognition.
- **Batch workflows:** no multiple-file queue, folder processing, or integrated production CLI; backend command-line examples exist.
- **Recognition options:** no speaker diarization, speech translation, configurable VAD/noise handling, vocabulary prompts, or confidence display. Silence handling is only a conservative RMS gate.
- **Recording flexibility:** no pause/resume, automatic device hot-plug monitoring, or stable identification of microphones with identical names; only F32/I16/U16 input formats are handled.
- **Model management:** no download resume, deletion UI, installed-model integrity checking, or meaningful model-format validation before selection/import.
- **GPU diagnostics:** no physical GPU selector, actual-device reporting, or explicit automatic retry on CPU after a GPU initialization failure.
- **LLM controls:** no model picker, context-length estimation/chunking, generation parameter controls, saved prompt templates, conversation history, or integrated server/model management. The first advertised model is always selected.
- **Localization:** application strings are hard-coded in English; there is no application translation infrastructure.
- **Distribution maturity:** no macOS bundle/installer integration, signed Windows releases, automatic application updates, or Flathub publication workflow. Clean-machine microphone/GPU and installed-package validation remain important gaps.

## Review and validation

Reviewed application code, test coverage, documentation, and the main packaging/release paths. No application behavior was changed for this report.

- `cargo test --locked`: **43 passed, 1 ignored**. The ignored test requires a real Whisper model.
- Re-ran the GTK surface test with `--nocapture`: passed, with no display-skip message.
- Flatpak packaging unit tests: **7 passed**; Windows packaging unit tests: **7 passed**.
- `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`, and the Flatpak locked-source/identity checker: passed. Vendored/generated Whisper code emits warnings.
- Reproduced the spacing issue with a standalone probe of the existing reconciliation/serialization code.

Real microphone capture, real-model inference, GPU backends, external LLM servers, download interruption/replacement failures, and fresh Windows/macOS/Flatpak installations were **not** exercised in this review. Passing unit tests do not establish those runtime guarantees.
