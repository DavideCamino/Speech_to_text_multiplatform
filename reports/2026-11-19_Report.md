# Speech2Text — Code Review Report

**Date:** 2026-11-19 · **Revision:** `66168e4` (`dev`, Cargo version 1.0.0)

**Priority:** Fix recovery-file preservation and silent acceptance of truncated recordings first. Both were reproduced against the current library with temporary local files, despite the default test suite passing. The remaining findings are source-review findings unless noted. High means potential loss of work or undetected incomplete results; medium means impaired operation or a significant coverage gap; low means maintenance, clarity, or narrowly scoped coverage issues.

## High risk

### 1. A later autosave overwrites the recovery file that startup promises to preserve

`src/ui/mod.rs::build_loaded` reports an unreadable recovery file as preserved but retains no state distinguishing it from an unused recovery path. `src/ui/recovery_controller.rs::autosave_and_close` subsequently calls `src/recovery.rs::save` at that same path; `persist(path)` replaces it. This matters for a recovery file from a newer version as well as a damaged file that a user could repair. **Probe:** wrote invalid bytes to `recovery.json`, called `load` (error), then saved a new session there (success); the original bytes were gone. The load alone is nondestructive; the loss is on the *next save*.

**Fix and regression:** preserve the unreadable file under a separate, non-clobbering name, or ask before replacing it. Test the entire load-failure → new work → Autosave & Close sequence and verify both sessions' bytes survive.

### 2. A physically truncated WAV can be reported as a complete transcription

`src/audio/decode.rs::next_samples` treats every packet-reader `UnexpectedEof` as a clean end. `src/transcription/worker.rs::file_windows` then flushes the last window and emits progress 1.0 and success; the queue has no error to summarize. **Probe:** created a two-second mono PCM WAV at 16 kHz, then truncated the payload to one second without updating its header. `AudioFile::open` reported `Some(2.0)` seconds; `next_samples` returned exactly 16,000 samples followed by clean EOF, not an error. This verifies the decoder behavior; the downstream success path was traced, not run through Whisper.

**Fix and regression:** for formats with an authoritative length, distinguish an ordinary end from a short read. Preserve already recognized text but flag the file as incomplete. Test a complete and truncated PCM fixture side by side; do not treat approximate compressed-format duration estimates as exact lengths.

This also affects users who successfully saved recovery to a different, writable data directory. | Offer **Retry** and **Exit without updating preferences** after a final-save failure. ## Low risk — unused paths, duplication, and documentation

- **Obsolete audio chooser branch.** `src/ui/dialogs.rs::open(window, model, …)` has exactly one production caller (`connect_model_actions`), always with `true`. The `false` audio filter/title duplicates the live `open_audio` implementation. Rename it `open_model`, remove the obsolete branch, and share common filter/error setup as appropriate. Also align the model filter (`*.bin`) with the library's acceptance of `.BIN`.
- **Duplicate preference submissions.** In `src/ui/actions.rs::connect_preferences_actions`, STT Apply persists controls and closes the settings window; the close-request handler persists controls again. LLM Apply has the same pattern in `src/ui/rewrite.rs`. `SaveWorker` can coalesce queued snapshots, but this does not guarantee one disk write. Give one callback ownership of saving and verify close-without-Apply still has its intended behavior.
- **Two LLM discovery paths.** The UI uses `start_configured`/`start_loading`; in-tree callers of public `llm::start` are in `tests/llm.rs`. Its `Client::model` separately reads/parses `/v1/models`, while `Client::models` already supports that endpoint as a fallback. This is **not proof the public API is unused externally**. Share bounded reading/parsing and keep a thin compatibility wrapper if needed. Correct the `start_configured` doc comment: generating checks readiness; it does not load the model.
- **Cleared queues retain hidden rows.** Cancel, completion and close clear `AudioQueue.files` without rebuilding `audio_list` (`transcription_controller.rs`, `lifecycle.rs`). Refresh hides the expander, but its labels, buttons and controllers remain until the next rebuild or window destruction. Clear the widget/model together; assert zero child rows after cancelling a large selection, not just an invisible expander.
- **Contradictory feature list.** `README.md:104` still says there is no batch-file queue; lines 30–38 document the implemented queue. Remove that limitation and distinguish *no persistent/resumable queue* from *no queue*.

## Missing features — distinct from bugs

- **Medium: recovery between explicit saves.** Recovery is opt-in at close, not periodic; after restoration the saved copy is consumed. A crash during a long recording/editing session can therefore lose the entire unexported draft. If adding checkpoints, make retention, deletion, and the unencrypted storage of sensitive text explicit. Do not persist audio or credentials by default (`README.md:54–56,88–95`).
- **Medium: long-transcript rewriting.** `Client::generate` submits the full source in one request. There is no model-context preflight, splitting, or resume; a transcript that succeeds locally can fail at rewrite time. Start with a clear context-limit diagnostic and user-controlled chunking rather than silently truncating (`README.md:109`).
- **Low: timed subtitle editing.** Text edits and original SRT are deliberately separate (`src/ui/transcript_state.rs`, `README.md:52,107`). Users can correct text but cannot export those corrections with timings. Add a cue editor rather than silently assigning timings to arbitrary free-text edits. Translation and speaker diarization are also documented omissions, not regressions in the current transcription contract.

## Test quality and verification

**Executed on Linux, default CPU features:**

| Check | Result |
|---|---|

One native-inference cancellation test ignored because it requires a local Whisper model. Binary and example harnesses had zero tests. |

| `cargo fmt --all --check`; `cargo clippy --offline --locked --all-targets -- -D warnings` | Both exited successfully. Cargo also reported warnings in the vendored Whisper dependency, not first-party dead-code diagnostics. |

**Tests to improve rather than count as coverage:**

- **Medium — GTK can pass without testing GTK.** `src/ui/tests/mod.rs::settings_pages_and_menu_surfaces_build` returns success on `gtk::init()` failure, skipping dozens of unrelated helper scenarios. Linux CI explicitly checks the skip message; plain local `cargo test` does not. Keep GTK on one thread, but make an intended GUI run fail loudly and identify the scenario that failed. Don't remove the substantive queue/recovery/renderer cases.
- **Low — version fixture doesn't test version handling.** In `src/recovery.rs::tests::invalid_files_and_failed_saves_preserve_existing_data`, `{"version":999}` lacks the required transcript/rewrite fields, so deserialization fails before `Snapshot::validate` checks the version. The invalid-*save* case tests a different path. Serialize a complete future-version snapshot for the load test and assert the version-specific error.
- **Low — redundant ownership assertion setup.** `tests/backend.rs::worker_receives_owned_context_and_reports_invalid_input_without_panicking` passes `context.clone()` then clears the original. This cannot change the owned `String` passed to `start`; those operations add no coverage. Pass the string directly and retain the valuable NUL rejection and private-text redaction assertions.
- **Low — menu smoke check can pass with broken actions.** `src/ui/tests/surfaces.rs` checks `n_items() == 3` and that accelerators parse. Three miswired entries still pass. Assert the expected action IDs resolve on the window and exercise the binding to the intended command. Keep the GTK construction check.

**Limits:** No native GPU, physical microphone, real LLM service, Windows installation, or release Flatpak run was performed. Model publication and settings now use same-directory staging; the earlier reports' delete-before-replace and in-place truncation findings should not be carried forward as current defects. A green suite is evidence about the exercised paths, not a substitute for the two failure-path regressions above.
